# Migration Log

## Phase 0 — Audit

- Read the existing route setup, all five pages and content modules, global styles, theme utilities, API mocks, link/layout components, every component, `PORTING.md`, and project configuration.
- No application files or dependencies changed. The Phase 0 gate passed; see [MIGRATION_PLAN.md](./MIGRATION_PLAN.md).
- Theme fallback deviation (approved): the old pre-paint script reads `localStorage['breto-theme']`; only the exact value `dark` adds `dark` to `<html>`, and every other value removes it. If reading storage throws, the empty/default class remains light. `useTheme()` also falls back to light for missing/invalid/blocked storage. In Phase 3, the new pre-paint script and client hook will honor a saved `dark` or `light`; when there is no valid saved value or storage is unavailable, they will use `matchMedia('(prefers-color-scheme: dark)')` (dark when it matches, light otherwise), falling back to light if that check throws. Thus an unsaved system-dark visitor will now see dark mode instead of the old light mode.
- `FILE_STRUCTURE.md` initially incorrectly reported the two tracked `public/assets/aistudio/` files as deleted. Phase 6 corrected the document; both assets remain at their original paths.
